= Лабораторна робота №9

*Тема:* React State та Effects: Context API, useReducer, useEffect і Custom Hooks.

*Мета:* навчитися організовувати стан React-застосунку, коли одного локального `useState` стає недостатньо.
Опанувати підняття стану, Context API, `useReducer`, побічні ефекти, роботу з `localStorage` та створення власних hooks.

Лабораторна є продовженням лабораторної роботи №8.
Необхідно продовжити розробку застосунку **Study Planner**.

== Вимоги до звіту

. Використовувати React та TypeScript.
. Використовувати функціональні компоненти та hooks.
. Використати Context API для спільного стану.
. Використати `useReducer` щонайменше для одного набору пов'язаних змін стану.
. Використати `useEffect` для роботи з побічним ефектом.
. Реалізувати збереження даних у `localStorage`.
. Винести повторно використовувану логіку в Custom Hook.
. Дотримуватися ESLint та єдиного стилю коду.
. Код повинен бути розміщений в особистому GitHub репозиторії студента.
. Дотримуватися Conventional Commits.

== Практична частина

=== 1. Розвиток Study Planner

Продовжити проєкт з лабораторної роботи №8.
Не видаляти вже реалізований функціонал.

У застосунку повинні залишитися:

* створення завдання;
* зміна стану виконання;
* видалення;
* фільтрація;
* статистика.

=== 2. Підняття стану

Проаналізувати компоненти `TaskForm`, `TaskList`, `TaskFilters` та `TaskStats`.

State, який використовується кількома компонентами, винести на спільний рівень.
Заборонено дублювати один і той самий стан у кількох незалежних компонентах.

Продемонструвати в коді передачу даних і callback-функцій через props там, де це доречно.

=== 3. useReducer

Перенести основні операції над завданнями у reducer.

Створити тип дій щонайменше для:

* `add`;
* `toggle`;
* `remove`.

За потреби додати:

* `update`;
* `clearCompleted`;
* `reset`.

Reducer не повинен містити UI-логіку або звернення до DOM.

=== 4. Context API

Створити `TaskContext` та `TaskProvider`.

Через Context зробити доступними:

* список завдань;
* поточний фільтр;
* дії зміни стану.

Не потрібно передавати всі ці значення через декілька рівнів props.

Компоненти, які не використовують конкретне значення Context, не повинні отримувати його через props лише «про запас».

=== 5. localStorage та useEffect

Реалізувати збереження списку завдань у `localStorage`.

Вимоги:

. при зміні списку завдань дані оновлюються в `localStorage`;
. при першому завантаженні застосунку збережені дані відновлюються;
. якщо збережених даних немає або вони пошкоджені, застосунок використовує початковий список;
. робота з `localStorage` виконується як побічний ефект.

=== 6. Custom Hook

Створити власний hook для роботи з `localStorage`, наприклад:

[source,typescript]
----
useLocalStorage<T>(key, initialValue)
----

Hook повинен уміти:

* читати початкове значення;
* повертати актуальне значення;
* оновлювати значення;
* серіалізувати дані;
* безпечно обробляти відсутність збереженого значення.

За бажанням цей hook можна зробити універсальним і використати не лише для tasks.

=== 7. Фільтр та derived state

Поточний список завдань для відображення не потрібно дублювати в окремому state.

Фільтрований список повинен обчислюватися з основного state.

Статистика також повинна обчислюватися з актуального списку завдань, а не з окремих лічильників, які легко розсинхронізувати.

=== 8. UX-стани

Додати до інтерфейсу:

* повідомлення, коли завдань немає;
* індикацію активного фільтра;
* підтвердження успішного додавання або іншої дії без використання `alert`.

Повідомлення може бути реалізоване простим компонентом `Toast` або inline-блоком.

=== 9. Додаткові завдання

. Перемикач «Показувати тільки високий пріоритет».
. Масове завершення усіх невиконаних завдань.
. Відновлення останньої видаленої задачі.
. Збереження активного фільтра у `localStorage`.
. Окремий `ThemeContext` для світлої/темної теми.
